# Workflow: Meeting (Sync Ritual)

## Purpose

Point de synchronisation transverse entre les trois branches de Nexus AI (Project, Technique, Marketing), pour éviter que chaque agent avance en silo sans visibilité sur l'état des autres branches.

## Trigger

Cadence régulière (par cycle de sprint — voir `sprint.md`) ou déclenché ponctuellement par le CEO en cas d'arbitrage nécessitant l'avis de plusieurs branches.

## Chain

```
Project Manager (état des projets en cours)
Software Architect (état technique, blocages)
Marketing Manager (état croissance, signaux remontés)
        │
        ▼
CEO (arbitrages si nécessaire, priorités confirmées ou ajustées)
```

## Participating Agents

CEO, Project Manager, Software Architect, Marketing Manager. Les agents de chaque branche remontent leur état via leur manager respectif plutôt que de participer individuellement.

## Notes

- Ce n'est pas un lieu de décision d'exécution — les décisions d'exécution restent dans le mandat de chaque agent spécialisé.
- Sert à détecter tôt les blocages inter-branches (ex. un projet bloqué côté technique alors que le marketing a déjà planifié une communication).
